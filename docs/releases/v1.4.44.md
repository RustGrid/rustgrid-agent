# rustgrid-agent v1.4.44

This patch release makes repository mutation a graph capability so initial
implementation, validation repair, and diff-review repair follow the same
target-bound event and evidence contracts without special-casing ticket or node
types.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Define repository-read, repository-mutation, validation, repair, review, and
  publication capabilities centrally for execution-node kinds.
- Resolve all mutation events through an intent-neutral context containing the
  owning node, mutation intent, repository target, target path, fingerprint,
  and revision producer.
- Route mutation tools and reducers by capability while preserving the
  implementation barrier semantics of initial source and test operations.
- Reserve validation-repair attempts only when provider work is admitted,
  consume them when the provider call completes, and release them without
  charging the repair budget otherwise.
- Emit structured capability resolution, mutation ownership, repair admission,
  target selection, activation idempotency, and attempt lifecycle telemetry.

## Fixed

- Let validation and diff-review repair nodes own mutation evidence and target
  revisions without changing the completed status or historical evidence of
  their originating implementation nodes.
- Make duplicate validation-repair activation a true replay no-op with one
  durable node and event and no attempt consumption before provider admission.
- Preserve repair-node resume identity and retry classification through the
  structured `OrchestrationContractFailure` boundary when a mutation event is
  incompatible with its node capability or repository target.
- Keep legacy checkpoint replay compatible while validating new capability,
  ownership, lifecycle, and repair-accounting invariants.

## Compatibility and deployment order

CLI commands, signed manifests, hosted HTTP endpoints, terminal outcomes,
publication behavior, and existing checkpoint type paths remain compatible.
New node kinds, capability-derived projections, mutation context, repair
reservations, and telemetry are additive, and new persisted collections default
cleanly when older journals are replayed.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. After the protected release completes,
pin the exact v1.4.44 Linux archive URL and SHA-256 published by the workflow.

## Verification

The release candidate passes formatting, strict Clippy, 610 library tests, 14
API contract tests, 10 CLI tests, 8 hosted-orchestrator replay tests, the npm
quality-gate build, and compilation from the packaged source archive using the
pinned Rust 1.94 toolchain. Regression coverage includes the node-capability
matrix, mutation-event ownership, repair evidence isolation, duplicate repair
activation, provider-admission accounting, released and consumed reservations,
typed contract failure, retryability, and repair-node resume identity.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL,
checksum, container deployment, and Homebrew installations to v1.4.43. Do not
replace or mutate the v1.4.44 tag or release assets. Additive node kinds,
reservation records, target revision producers, and telemetry may remain stored
during rollback.
