# rustgrid-agent v1.13.0

In this release Claude Code IDE sessions work under the project's architecture
contract, the same way cloud runs do, and they can raise an escalation for an
architect. Runs on a ticket whose escalations an architect has already decided
now follow that decision instead of being blocked again. Agents also now see
the contract's guardrails and protected paths, which the worker used to drop.

## Install or upgrade

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

Workers pick up the new version when they restart. There is no need to run
`rustgrid-agent trace install` again.

## Added

- **Architecture contract in IDE sessions.** When the project defines an
  architecture, `/rustgrid-link` writes it to `architecture.md` next to
  `ticket.md`. That file includes the plan check Claude follows, the ticket's
  declared boundaries, and the contract's guardrails and protected paths.
  When Claude's reply ends with the plan check's escalation lines
  (`RUSTGRID_AGENT_STATUS: ESCALATE`, `RUSTGRID_ESCALATION_BOUNDARIES`,
  `RUSTGRID_ESCALATION_REASON`, `RUSTGRID_PROPOSED_CHANGE`), the trace hook
  raises the escalation on the ticket for an architect. If an escalation cannot
  be raised, the error is kept in `architecture.error` next to `ticket.md`.

## Fixed

- **Decided escalations are followed.** A run after an architect decided an
  escalation now gets the decision. The manifest's new `decided_escalations`
  field (RustGrid API 2.2.0) lists the ticket's approved and rejected
  escalations with the architect's resolution. They reach the prompt and, in
  IDE sessions, the linked context.
  - An approved escalation's boundaries count as declared in the worker's diff
    check.
  - A rejection's guidance tells the agent how to stay inside the boundaries.

  Before, the next run never saw the decision. After an approval, its diff
  check raised the same escalation again and blocked, and a rejection's
  guidance never reached the agent.
- **Guardrails and protected paths reach the agent.** When the worker read the
  manifest it dropped the contract's guardrails, protected paths and
  `standard`, and the boundaries' `access`. They are now kept and included in
  the prompt.

## Compatibility

- Works with the same RustGrid as v1.12.0. `decided_escalations` is optional:
  older servers omit it, it defaults to none, and runs behave as in v1.12.0.
  Deploy RustGrid API 2.2.0 to get decisions into runs.
- A decision made under an earlier version of the contract may name a boundary
  that has since been removed. That boundary is ignored rather than rejecting
  the manifest.
- Session state, installed hooks and the execution manifest version (`2`) are
  unchanged.
- Projects without an architecture are unaffected. No `architecture.md` is
  written, and no plan check is enforced.

## Known limitations

- The diff check enforces only path scope. `may_depend_on`, rules and
  decisions are enforced through the prompt, CI and review.
- In IDE sessions the plan check is guidance for Claude. The hook raises
  escalations Claude reports, but it does not block edits outside the declared
  boundaries.
- See [known limitations](../known-limitations.md).

## Verification

The release candidate must pass formatting, strict Clippy, the full unit and
integration test suite, npm build, package verification, packaged-source
compilation, Homebrew formula syntax validation, and the version smoke test.

## Rollback

Reinstall v1.12.0. Do not replace or mutate the v1.13.0 tag or release assets.
After a rollback, IDE sessions no longer get `architecture.md` or raise
escalations, and runs after a decided escalation may again be blocked by the
same escalation.
