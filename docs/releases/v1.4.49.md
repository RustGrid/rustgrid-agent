# rustgrid-agent v1.4.49

This patch release allows a verified validation repair to persist its
authoritative tool checkpoint and continue into the existing validation rerun.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Fixed

- Mark the existing notebook-bearing tool event as an authoritative tool
  checkpoint using a structured event type.
- Let the RustGrid backend apply its bounded 1 MiB checkpoint allowance instead
  of rejecting the post-repair request under the generic 256 KiB event limit.
- Continue from a completed validation-repair node into the existing
  validation-rerun scheduling and command execution path.

## Compatibility and deployment order

Deploy RustGrid backend commit `ff468a39e8d5b063a2c7b2dad65cb737b5268141`
before pinning hosted workers to v1.4.49. Older backends do not recognize the
authoritative tool-checkpoint classification and can reject a large repaired
notebook with `execution_event_invalid`.

Discovery, planning, implementation mutation behavior, validation parsing,
repair selection, repair-node architecture, budgets, publication, and terminal
handling are unchanged.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. After the protected release completes,
pin the exact v1.4.49 Linux archive URL and SHA-256 published by the workflow.

## Verification

The worker release candidate passes formatting, strict Clippy, the full test
suite, package verification, and packaged-source compilation using the pinned
Rust 1.94 toolchain. The backend contract passes strict Clippy, all 66
`ticket-http` tests, and the event-sanitization tests. The focused regression
proves the completed-repair checkpoint is accepted while ordinary events retain
their 256 KiB limit and validation rerun scheduling remains accepted.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL,
checksum, container deployment, and Homebrew installations to v1.4.48. The
additive backend checkpoint classification may remain deployed. Do not replace
or mutate the v1.4.49 tag or release assets.
