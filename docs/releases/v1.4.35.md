# rustgrid-agent v1.4.35

This patch release makes mutation fallback strategies executable provider tool
policies. The worker now selects, enforces, journals, and verifies a bounded
strategy from generic repository evidence rather than relying on advisory
instructions or ticket-specific behavior.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Represent mutation strategies, allowed tools, repair transitions, and budget
  consumption with typed contracts.
- Bind each provider request to an exact tool surface and required tool choice,
  with preflight validation before dispatch and response validation afterward.
- Choose patching or whole-file replacement using target lifecycle, bounded
  size and context evidence, repository state, and prior typed failures.
- Journal replay-safe allowance decisions, rejected provider responses,
  application results, repair evidence, and target verification.
- Replace vulnerable npm-bundled `brace-expansion`, `ip-address`, and `undici`
  packages in the container with explicitly pinned patched versions.

## Fixed

- Prevent providers from bypassing the selected strategy with mixed, missing,
  unexpected, or disallowed mutation tool calls.
- Require typed application failure evidence and remaining budget before a
  fallback transition is allowed.
- Apply the same operation-aware policy to existing files, new files,
  deletions, renames, and moves without hardcoded ticket or framework concepts.
- Preserve rejected mutation attempts in telemetry and recovery without
  treating them as repository changes or consuming unrelated budgets.
- Keep safe cancellation, healthy blocked, partial-reviewable, and terminal
  results distinct from infrastructure failure when mutation cannot continue.
- Remove fixable high-severity findings from npm's bundled container runtime.

## Compatibility and backend deployment

Provider mutation requests are stricter but retain the existing hosted mission,
journal, telemetry, publication, and completion payload shapes. Older journals
remain readable; new policy evidence is additive and replay-safe.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. Deployment must pin the exact v1.4.35
Linux archive URL and SHA-256 from the completed protected release workflow.

## Verification

Formatting, strict Clippy across all targets and features, dependency policy,
secret and generated-contract checks, packaged-source compilation, JavaScript
quality gates, and the full locked test suite pass. Container verification also
covers image construction, runtime smoke tests, exact security-package pins,
and a high-severity vulnerability scan.

Regression coverage includes request preflight, exact tool enforcement,
provider response rejection, typed fallback transitions, repair budgets,
operation-aware target lifecycles, replay-safe journals, telemetry, terminal
outcome preservation, and repository verification.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, container deployment, and Homebrew installations to v1.4.34. Do not
replace or mutate the v1.4.35 tag or release assets. Journals written by this
release remain readable by v1.4.35 during recovery.
