# rustgrid-agent v1.4.26

This patch release makes hosted planning a bounded structured-artifact phase.
It reuses discovery evidence, reserves the second planning call for targeted
plan repair, and continues deterministically when provider output cannot be
accepted inside the planning budget.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Select typed `BuildPlan`, `RepairPlan`, and `ResolveEvidenceGap` actions from
  the accepted impact map, validation state, and current repository evidence.
- Restrict plan construction and repair to forced
  `record_implementation_plan` calls with a 4,096-token output cap; only a
  concrete uncached evidence gap may expose repository read or search tools.
- Supply planning with the ticket goal, acceptance criteria, accepted impact
  map, inspected paths, bounded candidate-file excerpts, architecture
  findings, related tests, repository fingerprint, and package validation
  commands already captured during discovery.
- Reserve one of the planning node's two calls and one repair attempt for a
  compact invalid-plan correction.

## Fixed

- Serve unchanged single and batch planning reads from the fingerprint-bound
  evidence cache without recording duplicate reads as the node's final
  successful action.
- Convert invalid first-plan output into a typed recoverable planning failure
  so the next reconciliation selects the low-reasoning `RepairPlan` action.
- Build a conservative implementation plan from the accepted impact map when
  model plan recording exhausts its bounded allowance. Theme work preserves
  provider restoration and cycling, selector accessibility, semantic palette,
  and focused selection, persistence, restoration, default, and regression
  coverage intents.
- Validate deterministic fallback plans normally, derive validation gates from
  `package.json`, finalize authoritative post-plan complexity, preserve spent
  discovery and planning usage, materialize downstream nodes, and select the
  first ready mutation.
- Keep accepted normalized impact maps free of a failure layer and preserve
  original diagnostics only as non-blocking normalization metadata.

## Compatibility, security, and known limitations

The new planning action and artifact metadata fields are serializable and
default-compatible with existing checkpoints. Repository evidence remains
bound to the repository fingerprint. No new credential scope, repository
permission, provider, or external integration is introduced.

The coordinated RustGrid backend terminal-outcome precedence fix is merged and
its focused `blocked_no_diff` regression passes. Production deployment of that
backend remains separate from this agent publication.

Artifact publication updates the GitHub release, native binaries, Homebrew
formula, SBOM, attestations, and container. It does not update the production
worker artifact pin automatically. Production must use the exact v1.4.26 Linux
archive URL and SHA-256 published by the completed protected workflow.

## Verification

The complete suite passes 447 unit tests, 14 API-contract tests, 10 CLI tests,
and 8 hosted-orchestrator replay tests. Formatting, strict Clippy, package
verification, and the repository build gate pass. Focused coverage proves
typed planning selection, forced artifact-only tools, bounded build-plus-repair
cost, discovery evidence reuse, duplicate-read caching, deterministic fallback
validation, normalized artifact telemetry, and authoritative post-plan graph
materialization. The merged backend terminal-precedence regression also passes.

## Rollback

Stop new hosted dispatches before restoring the RustGrid worker download URL
and SHA, canonical workflows, and Homebrew installations to v1.4.25. Do not
replace or mutate the v1.4.26 tag or release assets. Existing execution
checkpoints remain backward readable.
