# rustgrid-agent v1.4.43

This patch release isolates validation-repair execution from completed initial
implementation so later validation work cannot reopen or rewrite an already
verified source or test mutation.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Create a distinct, target-bound `ValidationRepair` graph node for every
  admitted validation-failure revision and selected repository target.
- Give validation repair an independent attempt ledger, session-owned budget,
  operation evidence stream, target revision record, and resume identity.
- Project initial implementation completion, active repair, and validation
  freshness independently while retaining the shared repository-target
  identity.
- Emit structured repair-node creation, activation, target linkage, operation
  verification, completion, and implementation-preservation telemetry.

## Fixed

- Prevent completed source and test mutation nodes from transitioning back to
  ready, running, repairing, or pending during validation repair.
- Preserve original implementation attempts and successful operation evidence
  as immutable historical facts after later repairs of the same target.
- Keep the implementation barrier and completed-change projection satisfied
  throughout repair, while making prior validation evidence stale after a
  verified repair mutation.
- Resume the active repair node from a durable checkpoint without replaying
  completed implementation nodes or consuming implementation-repair budget.
- Reject any completed implementation evidence paired with a non-completed
  implementation node before persistence, retaining the exact
  `OrchestrationStateInvariantFailure / completed_implementation_node_reopened
  / validation_repair` classification and resumability.
- Continue directly to the originating validation gate after a meaningful
  repair and bind the rerun to the repaired repository fingerprint.

## Compatibility and deployment order

CLI commands, signed manifests, hosted HTTP endpoints, terminal outcomes,
publication behavior, and existing checkpoint type paths remain compatible.
New repair-node metadata, evidence, revision history, and session fields are
additive and defaulted for legacy journal replay.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. After the protected release completes,
pin the exact v1.4.43 Linux archive URL and SHA-256 published by the workflow.

## Verification

The release candidate passes formatting, strict Clippy, 605 library tests, 14
API contract tests, 10 CLI tests, 8 hosted-orchestrator replay tests, and
compilation from the packaged source archive using the pinned Rust 1.94
toolchain. Regression coverage includes completed source and test monotonicity,
the four-target source A/B/C and test D repair scenario, repair success and
failure, implementation fallback followed by validation repair, validation
freshness, exact failure taxonomy, and checkpoint resume.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL,
checksum, container deployment, and Homebrew installations to v1.4.42. Do not
replace or mutate the v1.4.43 tag or release assets. Additive repair-node,
evidence, revision, telemetry, and checkpoint fields may remain stored during
rollback.
