# rustgrid-agent v1.4.27

This patch release makes hosted validation process-aware and recovery-safe. It
separates graph scheduling deadlines from gate execution limits, prioritizes
focused changed-test evidence, and preserves useful changes when worker
infrastructure prevents validation from completing.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Assign gate-specific scheduling, startup-grace, inactivity, absolute-process,
  and retry policies for focused tests, full suites, builds, lint/typecheck,
  dependency installation, browser/E2E, and custom validation.
- Derive a deterministic validation chain from the accepted implementation
  plan: dependency bootstrap, focused tests related to changed targets,
  lint/typecheck, full test suite, build, browser/E2E, then custom gates.
- Persist dependency bootstrap evidence keyed by command, lock hash, and
  repository fingerprint so unchanged successful setup can be reused without
  suppressing installation after dependency changes.
- Emit validation start, activity, completion, timeout, retry, configured
  budget, elapsed-time, output-byte, repository-fingerprint, and exit-status
  telemetry.
- Specialize mutation execution into read-only target inspection and verified
  target mutation actions while retaining compatibility with older serialized
  decisions.

## Fixed

- Do not shorten a gate's process timeout to the validation node's scheduling
  deadline. Node duration controls when work may start; the gate policy and
  remaining mission deadline control how long the admitted process may run.
- Refresh process activity from stdout and stderr independently, apply a hard
  absolute limit even while output continues, and report rich timeout
  diagnostics instead of a generic gate failure.
- Retry one transient infrastructure failure without a model call when the
  remaining mission budget can fund a full retry; code/test assertion failures
  remain non-retryable and continue through source repair.
- Materialize focused tests found from existing changed test targets before
  broad suites, and keep unstarted downstream validation nodes precisely ready,
  pending, skipped, or superseded rather than reporting them as running.
- Preserve an applied diff as a prominently incomplete draft pull request when
  validation times out after its infrastructure retry. The mission remains
  healthy and partial-reviewable, with no false claim that an assertion failed.
- Reopen validation and finalization on continuation while preserving applied
  mutation targets and preventing duplicate mutation dispatch.

## Compatibility, security, and known limitations

The new mutation action defaults to read-only inspection when older serialized
decisions omit the field. Existing notebooks and execution checkpoints remain
readable. No new credentials, repository permissions, providers, dependency
versions, or external integrations are introduced.

Hosted execution still requires the canonical GitHub Actions OIDC and Linux
cgroup-v2 containment boundary. Artifact publication does not update the
production backend's agent download URL and checksum automatically; deployment
must pin the exact v1.4.27 Linux archive and SHA-256 from the completed protected
release workflow.

## Verification

The complete suite passes 453 unit tests, 14 API-contract tests, 10 CLI tests,
and 8 hosted-orchestrator replay tests. Formatting, strict Clippy, package
verification, and repository build gates pass. Regression coverage includes
gate-specific process budgets, independent stdout/stderr activity, focused-gate
ordering, bootstrap evidence reuse, model-free infrastructure retry, precise
validation statuses, fresh-run timeout draft publication, continuation from
validation, and inspect-before-mutate specialization.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.26. Do not replace
or mutate the v1.4.27 tag or release assets. Existing checkpoints remain
backward readable.
