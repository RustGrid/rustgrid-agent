# rustgrid-agent v1.4.29

This patch release establishes typed error boundaries across the agent runtime
and decomposes the hosted runtime and execution graph into bounded modules. It
makes retry, terminal-outcome, recovery, stale-write, and telemetry decisions
explicit and compiler-checked while preserving diagnostic source chains.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Define bounded error types for domain, hosted-runtime, provider,
  control-plane, repository, publication, journal, recovery, validation, and
  local-infrastructure boundaries, with explicit conversion into a top-level
  execution failure.
- Centralize exhaustive execution-failure mappings to terminal outcomes and
  telemetry codes, and carry retryability as structured data through
  conversions.
- Split the hosted runtime and execution graph into focused modules with
  explicit lifecycle, orchestration, transition, persistence, recovery,
  provider, publication, and telemetry contracts.
- Introduce typed sub-effect ports for repository, journal, control-plane, and
  publication operations so failure behavior can be exercised independently.
- Add `scripts/package-for-chatgpt.sh`, which secret-scans tracked source before
  producing a review archive that excludes credentials and untracked files.

## Fixed

- Make cancellation and lease loss distinct top-level failures so cancellation
  cannot be reported as local infrastructure failure and lease loss suppresses
  stale terminal writes.
- Remove string comparison used to recognize known failure classes while
  preserving CLI-facing context and diagnostic error chains.
- Redact authentication material from `Display`, `Debug`, and nested source
  formatting.
- Keep retryable control-plane and provider failures retryable across subsystem
  conversions, while permanent rejections remain non-retryable.
- Make the incremental stdout/stderr activity regression test independent of a
  machine-specific inactivity deadline while retaining assertions that both
  streams refresh process activity.

## Compatibility, security, and known limitations

The CLI boundary and one-time setup paths continue to use contextual `anyhow`
reporting; domain and orchestration contracts now expose typed failures. The
release introduces no credential, repository-permission, provider, dependency,
or external-integration changes.

Hosted execution still requires the canonical GitHub Actions OIDC and Linux
cgroup-v2 containment boundary. Artifact publication does not update the
production backend's agent download URL and checksum automatically; deployment
must pin the exact v1.4.29 Linux archive and SHA-256 from the completed protected
release workflow.

## Verification

The complete locked suite passes 499 unit tests, 14 API-contract tests, 10 CLI
tests, and 8 hosted-orchestrator replay tests. Formatting, strict Clippy,
package verification, npm build gates, and version checks pass. Regression
coverage includes exhaustive
error-to-outcome and error-to-telemetry mappings, retryability preservation,
lease-loss stale-write suppression, cancellation classification, sensitive
value redaction, source-chain preservation, modular graph transitions, and
incremental stdout/stderr process activity.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.28. Do not replace
or mutate the v1.4.29 tag or release assets. Existing checkpoints remain
backward readable.
