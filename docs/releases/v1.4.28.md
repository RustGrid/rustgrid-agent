# rustgrid-agent v1.4.28

This patch release makes hosted implementation target-bound and mutation-first.
It replaces the generic implementation loop with explicit, durable preparation,
mutation, verification, and repair actions so a localized edit cannot spend its
implementation budget rediscovering later targets.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Introduce typed `PrepareTargetContext`, `MutateTarget`,
  `VerifyTargetState`, and `RepairTarget` actions plus durable context-prepared
  and mutation-produced graph events.
- Assemble mutation context from the accepted plan and current-fingerprint
  evidence: exact target content, intent, assigned acceptance criteria,
  relevant impact areas, related-test excerpts, and preservation constraints.
- Expose only `apply_patch` and `replace_file` during mutation, and constrain
  both tool schemas to the exact active target path.
- Bound each mutation node to one normal model call and one optional repair
  call, using a 4,096-token medium-reasoning profile with required tool use and
  disabled parallel calls.

## Fixed

- Serve unchanged target evidence from the persisted cache without another
  provider call, repository operation, or progress-window charge, while
  emitting `worker.evidence_cache_hit` telemetry.
- Prevent repository searches, related-test discovery, unrestricted reads, and
  cross-target edits once a mutation node is active.
- Reject read-only, free-form, and successful-no-change mutation responses as
  `MutationNotProduced` instead of allowing repeated exploratory calls.
- Recompute repository state after a write and verify the exact target hash and
  changed path deterministically before recording `MutationApplied`.
- Treat an already-applied target as success without a repair call, and retain
  validation-failure recovery identity across the model-free verification
  action.
- Keep graph attempt accounting stable across preparation, mutation, and
  verification, and preserve later-target isolation until the active node is
  applied, failed, blocked, or superseded.
- Emit action-specific no-progress diagnostics with the active node and target,
  action call counts, requested read paths, cache duplicates, and mutation-tool
  usage.
- Check a repository command's terminal process state before its inactivity
  deadline on each polling tick, preventing completed short-lived commands from
  failing spuriously on slower macOS runners.

## Compatibility, security, and known limitations

Legacy repair decision decoding remains available for existing checkpoints,
while new reconciliation emits the typed repair action. The release introduces
no dependency, credential, repository-permission, provider, or external
integration changes.

Automated browser scenarios and screenshots remain execution evidence rather
than product or design approval. Missions with an outstanding human approval
criterion remain `complete_pending_external_review` until real approval
evidence is supplied.

Hosted execution still requires the canonical GitHub Actions OIDC and Linux
cgroup-v2 containment boundary. Artifact publication does not update the
production backend's agent download URL and checksum automatically; deployment
must pin the exact v1.4.28 Linux archive and SHA-256 from the completed protected
release workflow.

## Verification

The complete suite passes 455 unit tests, 14 API-contract tests, 10 CLI tests,
and 8 hosted-orchestrator replay tests. Formatting, strict Clippy, package
verification, npm build gates, and version checks pass. Regression coverage
includes explicit mutation-action sequencing, exact-path tool schemas,
current-fingerprint evidence reuse, bounded repair, deterministic verification,
already-applied targets, external human approval, and focused-validation
ordering.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.27. Do not replace
or mutate the v1.4.28 tag or release assets. Existing checkpoints remain
backward readable.
