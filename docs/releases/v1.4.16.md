# rustgrid-agent v1.4.16

This patch release fixes hosted multi-file mutation authorization and prevents
non-retryable plan metadata failures from consuming implementation budgets or
overriding valid resumable partial results.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Store implementation-plan targets as structured per-file objects with roles,
  new-file markers, target status, and optional logical parent change IDs.
- Normalize legacy semicolon-separated plan and notebook targets before any
  source-changing tool reaches mutation authorization.
- Add deterministic `repair_implementation_plan` evidence that records targets
  before and after normalization without consuming a model call.
- Emit implementation progress windows every five implementation or repair
  calls, including successful writes, changed paths, repeated failure codes,
  and the resulting orchestration action.
- Publish path-level planned, changed, verified, and blocking-criterion facts
  and clearer partial pull-request continuation summaries.

## Fixed

- Authorize a concrete file mutation when its normalized path is a member of
  the planned target set.
- Keep mutation preflight rejection separate from executed write failure and
  halt editing-tool switching after non-retryable metadata or policy failures.
- Cap genuine content repair at four failed writes per target and stop repeated
  zero-progress failure loops.
- Keep passing repository tests distinct from implementation completeness when
  required planned paths were not changed.
- Resume persisted legacy notebooks without repeating discovery, planning, or
  already completed work, including valid deletion targets.
- Preserve successful partial and blocked publications as healthy process
  outcomes whose authoritative worker result cannot be replaced by later
  workflow-run or workflow-job observations.

## Compatibility and known limitations

RustGrid must retain terminal worker-result precedence for `completed`,
`awaiting_external_review`, `needs_continuation`, `blocked`, `failed`,
`cancelled`, `timed_out`, and `lost` states. Older notebooks remain readable and
are normalized when restored.

Artifact publication updates the GitHub release, native binaries, Homebrew
formula, SBOM, attestations, and container. Production worker configuration must
still be updated to the exact published Linux archive URL and SHA-256 after the
protected release workflow completes.

## Verification

The complete worker suite passes 268 unit tests, 14 API-contract tests, and 10
CLI tests. Strict Clippy passes with warnings denied. Focused regression tests
cover structural plan repair, membership authorization, preflight accounting,
five-call zero-progress detection, per-target rollup, legacy notebook resume,
planned-versus-changed completion, partial publication, and unconditional
backend worker-result precedence.

## Rollback

Stop new hosted dispatches before restoring the RustGrid worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.15. Do not replace
or mutate the v1.4.16 tag or release assets. Persisted notebook, target-status,
preflight, and partial-result records remain available for audit and resume.
