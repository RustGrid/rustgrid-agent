# rustgrid-agent v1.9.0

This release puts an IDE session on its ticket's branch when you link it with
`/rustgrid-link`.

## Install or upgrade

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

Restart Claude Code after upgrading. There is no need to run
`rustgrid-agent trace install` again.

## Changed

- **`/rustgrid-link KEY` switches to the ticket's branch.** Before, linking
  kept whatever branch was checked out, so a session linked to one ticket could
  commit to another ticket's branch or to `main`. Linking now puts the
  repository on a branch named after the ticket, `agent/<key>-<title>`, the
  same naming the worker uses:
  - A branch that already names the ticket is kept, so sessions linked from
    the branch name are unchanged.
  - An existing `agent/<key>-<title>` branch is reused. Otherwise one is
    created from the current commit, and uncommitted changes come along.
  - Linking another ticket mid-session moves to that ticket's branch.
  - If git refuses the switch, for example because of local changes the
    target branch would overwrite, the session stays linked on its current
    branch. Claude tells you why and how to switch.
  - Outside a git repository, nothing changes.

## Compatibility

- Works with the same RustGrid as v1.8.2. Session state written by v1.8.x is
  read as is. Installed hooks are unchanged.
- The switch only creates or switches branches. Nothing is reset, stashed or
  discarded. Git hooks do not run during the switch.

## Known limitations

- RustGrid records the branch the session was on when the link started, not
  the ticket branch it moved to. The branch name needs the ticket's title,
  which arrives only in RustGrid's answer to the link.
- See [known limitations](../known-limitations.md).
