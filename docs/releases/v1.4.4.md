# rustgrid-agent v1.4.4

This release attributes hosted-execution commits to the GitHub account that
initiated the workflow, allowing GitHub and downstream deployment providers to
associate agent-created commits with a real account.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Hosted execution reads GitHub's immutable `GITHUB_ACTOR` and
  `GITHUB_ACTOR_ID` default workflow variables before repository work.
- Commits use the workflow actor's login as `user.name` and GitHub's
  `<id>+<login>@users.noreply.github.com` private email format as `user.email`.
- Workflow reruns retain the original workflow actor identity and privileges.

## Fixed

- Remove the hardcoded `rustgrid-agent@users.noreply.github.com` author email,
  which GitHub could not associate with an account and downstream deployment
  providers could therefore reject.
- Validate human and GitHub App bot actor identities and fail closed when the
  actor login or numeric account ID is missing or malformed.

## Compatibility and deployment

No new workflow input or secret is required. GitHub supplies `GITHUB_ACTOR` and
`GITHUB_ACTOR_ID` to every workflow step as default environment variables.
Canonical workflows must update their pinned agent download URL and SHA-256 to
the v1.4.4 Linux archive before new executions receive this fix.

Commits created by older agent versions retain their original author metadata.
A v1.4.4 continuation creates subsequent commits with the workflow actor's
GitHub-associated identity.

This release retains the v1.4.3 completion-aware execution contract. Deploy the
control-plane support for `partial_result` before deploying this worker version.

Artifact publication does not update canonical workflow references or deploy
workers. Regenerate affected workflows and complete staging certification
against the exact published image digest before production promotion.

## Rollback

If rollback is required, stop hosted dispatches and return canonical workflows
to `v1.4.3`. Version 1.4.3 uses the unmatched hardcoded commit email and may
reintroduce deployment rejection for agent-created commits. Do not replace or
mutate existing tags or release assets.
