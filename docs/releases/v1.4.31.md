# rustgrid-agent v1.4.31

This patch release preserves successful hosted domain outcomes and makes
completion decisions deterministic when the execution graph, validation gates,
and reviewed repository diff already provide sufficient evidence.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Construct one compact `CriterionEvidence` record per acceptance criterion
  from applied change IDs, changed paths, verified graph target IDs, relevant
  validation gates, diff-review findings, and external evidence requirements.
- Use a 3,072-output-token, low-reasoning completion request containing only
  normalized evidence summaries rather than the complete notebook, ticket
  body, source hunks, graph history, or validation logs.
- Skip completion-model dispatch when deterministic evidence already proves a
  complete or complete-pending-external-review result.
- Emit canonical terminal, workflow exit, completion evidence, criterion
  resolution, admission, skip, and external-review telemetry.
- Report call accounting separately for discovery, planning, initial target
  mutation, target repair, validation diagnosis, validation-repair mutation,
  diff review, and completion evaluation.

## Fixed

- Prevent a healthy, published domain result from being contradicted by a
  secondary worker result with a different mission outcome.
- Preserve exit code zero for complete, complete-pending-external-review,
  published partial-reviewable, and healthy resumable blocked outcomes.
- Make deterministic repository evidence authoritative for code criteria so an
  optional completion model cannot erase or downgrade it.
- Classify selection, cycling, local-storage persistence and restoration,
  fallback behavior, regression coverage, and build correctness as automated
  verification instead of external review.
- Return `complete_pending_external_review` when implementation and automated
  verification are complete and only product, design, visual, accessibility,
  or deployment review remains.
- Keep a review-pending pull request draft without treating the worker process
  or implementation as failed.
- Reject graph configurations whose completion node cannot fund its first
  compact action, and retain rejected admission telemetry without charging a
  provider call.

## Compatibility, security, and known limitations

The completion request and terminal telemetry changes are additive to the
existing control-plane contract. Existing persisted graph and notebook records
remain readable through defaulted fields. Completion requests intentionally do
not include full source files, captured validation output, provider secrets, or
the complete worker notebook.

The RustGrid control plane independently owns workflow-run reconciliation and
must retain a terminal worker result when later GitHub infrastructure metadata
arrives. Artifact publication does not update the production backend's agent
download URL and checksum automatically; deployment must pin the exact v1.4.31
Linux archive and SHA-256 from the completed protected release workflow.

## Verification

Formatting and strict Clippy pass for all targets and features. The complete
locked suite passes 511 library tests, 14 API-contract tests, 10 CLI tests, and
8 hosted-orchestrator replay tests. Coverage includes deterministic evidence
construction, automated-versus-external verification classification,
model-precedence protection, canonical terminal mapping, independent draft
state, completion-budget viability, compact request cost, and pre-provider call
accounting.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.30. Do not replace
or mutate the v1.4.31 tag or release assets. Existing checkpoints remain
backward readable.
