# rustgrid-agent v1.4.17

This patch release makes the hosted execution lifecycle deterministic after a
healthy multi-file implementation and prevents repeated validation from
consuming the remaining model budget.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Add a canonical hosted lifecycle with validated transitions through
  implementation, validation, diff review, completion evaluation, and
  publication.
- Make per-target status authoritative and derive structured remaining work
  instead of independently mutating completed and remaining lists.
- Persist a validation ledger containing normalized commands, fingerprints,
  source-tree and dependency-lock hashes, status, timing, output summaries, and
  evidence source.
- Assign ticket-complexity call budgets: a four-target ticket is capped at 20
  total calls, with implementation and repair capped at 12 and 6.
- Send phase-specific compact notebook context instead of the complete notebook
  and historical output on every model request.

## Fixed

- Exit implementation as soon as all required targets are applied in the final
  repository state. This no longer depends on `repository_snapshot`, an
  implementation declaration, or model-budget exhaustion.
- Reuse identical passed validation for an unchanged source tree, and prevent a
  failed gate from rerunning until source, configuration, or dependency state
  changes.
- Limit focused validation to three commands after a source mutation, required
  validation to six gates, full validation to eight minutes, and repair to two
  rounds.
- Stop four-call zero-progress loops even when there is no explicit tool error.
- Add ticket-size cost thresholds and phase wall-clock guardrails that preserve
  useful changes as resumable partial work.
- Checkpoint cancellation provenance, current target state, changed paths,
  validation evidence, source-tree hash, and exact resume phase before ending
  normally.
- Publish useful partial work and external-review-pending implementations
  without converting valid domain outcomes into failed GitHub Actions jobs.

## Compatibility and known limitations

Existing v1 notebook data remains readable. Structured remaining work,
validation evidence, and required gates use defaulted fields and are rewritten
at the next checkpoint. RustGrid must retain the terminal worker-result
precedence already enforced for workflow-run and workflow-job observations.

Artifact publication updates the GitHub release, native binaries, Homebrew
formula, SBOM, attestations, and container. It does not deploy a production
worker. Production must be updated to the exact v1.4.17 Linux archive URL and
SHA-256 after the protected workflow completes.

## Verification

The complete worker suite passes 276 unit tests, 14 API-contract tests, and 10
CLI tests. Strict Clippy passes with warnings denied, the locked release build
passes, and focused coverage reproduces the four-target AOPS-226 lifecycle,
tree-bound validation reuse, stale-evidence invalidation, lifecycle invariants,
compact context, cancellation semantics, and the 20-call ticket cap.

## Rollback

Stop new hosted dispatches before restoring the RustGrid worker download URL
and SHA, canonical workflows, and Homebrew installations to v1.4.16. Do not
replace or mutate the v1.4.17 tag or release assets. New notebook fields are
backward-compatible and remain available for audit and later resume.
