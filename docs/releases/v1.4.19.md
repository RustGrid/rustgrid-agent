# rustgrid-agent v1.4.19

This patch release fixes implementation-plan acceptance and deterministic
criterion-coverage repair so valid multi-change plans advance directly into
implementation.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Use canonical `ac-N` acceptance-criterion IDs in implementation plans and the
  planning tool contract.
- Validate criterion references and coverage over the complete plan while
  requiring each planned change to carry at least one relevant criterion.
- Keep criterion assignments scoped to the changes that implement them instead
  of copying unrelated criteria onto every change.

## Fixed

- Accept a four-change plan that collectively covers `ac-1` through `ac-9`
  even though no individual change covers all nine criteria.
- Assign a missing criterion to the uniquely most relevant existing change
  using impact-map path evidence and semantic relevance.
- Revalidate deterministic coverage repairs locally without spending another
  provider call; genuinely ambiguous placement continues through the bounded
  planning-repair path.
- Replace the provider candidate with the repaired plan before subsequent
  validation, persistence, telemetry, or implementation transition.

## Compatibility, security, and known limitations

Persisted plans using the legacy `acceptance_criteria` field or exact criterion
text remain readable and are normalized to canonical IDs when accepted. No new
credential scope, repository permission, mutation surface, or network access is
introduced. Deterministic repair requires one uniquely most relevant change;
ties or zero-evidence placement remain explicit planning-repair requests.

Artifact publication updates the GitHub release, native binaries, Homebrew
formula, SBOM, attestations, and container. It does not deploy a production
worker. Production must be updated separately to the exact v1.4.19 Linux
archive URL and SHA-256 after the protected release workflow completes.

## Verification

The complete locked worker suite passes 315 unit tests, 14 API-contract tests,
and 10 CLI tests. Formatting and strict Clippy pass with warnings denied.
Focused regressions prove collective `ac-1` through `ac-9` coverage and local
assignment of a missing `ac-9` to the palette change without another provider
call, followed by an implementation transition.

## Rollback

Stop new hosted dispatches before restoring the RustGrid worker download URL
and SHA, canonical workflows, and Homebrew installations to v1.4.18. Do not
replace or mutate the v1.4.19 tag or release assets. Canonical plan IDs remain
backward-compatible with legacy notebook input and available for later resume.
