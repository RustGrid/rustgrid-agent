# rustgrid-agent v1.4.39

This patch release makes hosted orchestration converge generically when a
repository operation is already satisfied, while bounding repeated decisions
and preserving truthful partial outcomes.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Represent applied and already-applied repository operations with typed
  outcomes, satisfied intent, immutable hashes, repository fingerprints, and
  replay-safe semantic identities.
- Complete already-satisfied mutation nodes atomically, refresh downstream
  readiness once, and preserve the graph revision on idempotent replay.
- Derive orchestration decisions and externally reported implementation,
  repair, validation, review, and publication phases from canonical graph
  state.
- Track successful lease renewal separately from semantic progress and use a
  typed cycle-guardrail cancellation initiator.
- Emit bounded convergence telemetry for stale-pointer reconciliation,
  decision deduplication, unchanged graph revisions, and deterministic cycle
  termination.

## Fixed

- Prevent already-applied modifications, creations, deletions, renames, moves,
  and validation repairs from repeatedly probing or dispatching the same work.
- Clear terminal active-node pointers and advance to the next runnable node
  without fabricating graph changes.
- Keep decision identity stable when only graph revision changes, while
  invalidating it for meaningful repository, validation, failure, budget, or
  publication changes.
- Stop identical deterministic cycles after two observations instead of
  consuming hundreds of model calls or emitting unbounded events.
- Preserve useful repository changes as an incomplete reviewable result when
  validation or local infrastructure cannot finish, including mutations
  completed through already-applied evidence.
- Carry validation-repair intent and failure identity through an
  already-applied repair and schedule the required validation rerun directly.
- Update the pinned container runtime to Node 24.18.1 to include upstream fixes
  for newly disclosed high-severity Node vulnerabilities.

## Compatibility and deployment order

The signed manifest, hosted HTTP endpoints, terminal callback, and CLI
contracts are unchanged. New checkpoint and telemetry fields are additive and
older checkpoints retain their existing defaults during replay.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. After the protected release completes,
pin the exact v1.4.39 Linux archive URL and SHA-256 published by the workflow.

## Verification

The release candidate passes formatting, strict Clippy across all targets and
features, 591 library tests, 14 API contract tests, 10 CLI tests, 8 hosted
orchestrator replay tests, and compilation from the packaged 192-file source
archive.

Regression coverage includes atomic already-applied convergence and replay,
stable semantic decision identity, stale active-node reconciliation,
graph-derived external phases, independent lease and progress liveness,
bounded event emission and cycle cancellation, validation-repair handoff, and
useful partial-diff preservation.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL,
checksum, container deployment, and Homebrew installations to v1.4.38. Do not
replace or mutate the v1.4.39 tag or release assets. The additive checkpoint
and telemetry fields may remain stored during an agent rollback.
