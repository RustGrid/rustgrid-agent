# rustgrid-agent v1.4.21

This patch release replaces fragmented hosted lifecycle decisions with one
canonical execution graph, a pure deterministic orchestrator, and replayable
domain events.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Represent discovery, planning, each planned target, required validation,
  diff review, completion evaluation, and publication as dependency-linked
  execution nodes.
- Make graph events, evidence, failures, publication state, cancellation, and
  budgets serializable and exactly replayable across worker attempts.
- Route every hosted action through a pure orchestrator whose output depends
  only on the immutable execution snapshot.
- Classify missions as tiny, small, medium, or large and apply deterministic
  model-call, repair, cost, and duration envelopes at both node and mission
  scope.
- Materialize compatibility notebook fields from graph state so existing API
  and resume consumers remain supported without becoming lifecycle authorities.

## Fixed

- Prevent completion and publication from bypassing required target work,
  current validation evidence, and final diff review.
- Bind reusable validation proof to the repository tree, dependency lock,
  normalized command, working directory, and relevant execution environment.
- Invalidate stale validation and finalization state after remote branch
  reconciliation, then require the canonical validation-to-publication route.
- Preserve reviewable partial work through budget exhaustion and internal
  orchestration recovery while keeping infrastructure failures and cancellation
  distinct.
- Complete an authorized draft-recovery publication as
  `partial_reviewable` instead of re-entering skipped normal finalization nodes.
- Replay attempts 17 through 20 deterministically, including validation reuse,
  read-failure recovery, collective acceptance-criterion coverage, and
  duplicate first-target advancement through all five planned targets.

## Compatibility, security, and known limitations

Legacy worker notebooks are imported once and then projected from the canonical
graph. Existing hosted API and manifest contracts remain compatible. This
release adds no credential scope, repository permission, or network access.
Recovery publication remains fail-closed unless the repository has a non-empty
diff, every required validation gate has current fingerprint-bound evidence,
the Git origin is the exact credential-free manifest repository, and the pull
request is a draft.

Artifact publication updates the GitHub release, native binaries, Homebrew
formula, SBOM, attestations, and container. It does not deploy a production
worker. Production must be updated separately to the exact v1.4.21 Linux
archive URL and SHA-256 after the protected release workflow completes.

## Verification

The complete locked worker suite passes 410 unit tests, 14 API-contract tests,
10 CLI tests, and 8 hosted-orchestrator replay tests. Formatting and strict
Clippy pass with warnings denied. The replay suite covers attempts 17 through
20 plus ten bounded mission benchmarks, and the Linux hosted path exercises
cgroup-contained recovery commit, push, draft pull-request publication, and
terminal partial outcome handling.

## Rollback

Stop new hosted dispatches before restoring the RustGrid worker download URL
and SHA, canonical workflows, and Homebrew installations to v1.4.20. Do not
replace or mutate the v1.4.21 tag or release assets. Persisted graph checkpoints
and notebooks remain available for a later continuation attempt.
