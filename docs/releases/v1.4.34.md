# rustgrid-agent v1.4.34

This patch release makes the hosted worker's structured domain result
authoritative over later process and workflow conclusions. A useful engineering
outcome can be healthy even when implementation work, external review, or a
safely recorded blocker remains.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Add one canonical terminal result containing the mission outcome, process
  health, reason code, domain status, publication record, completion evidence,
  remaining work, resumability, timestamp, and finality marker.
- Give every result a deterministic terminal ID and revision with explicit
  worker-domain, infrastructure-fallback, or administrative authority.
- Resolve terminal precedence from deterministic graph, validation,
  remaining-evidence, and publication facts before persistence.
- Classify unresolved evidence as external approval, manual inspection,
  missing automated validation, unresolved implementation, or incomplete
  infrastructure.
- Derive API completion, UI status, telemetry, compatibility fields, and
  process exit behavior from the canonical result.

## Fixed

- Exit successfully for healthy complete, externally pending,
  partial-reviewable, resumable blocked, and expected cancellation outcomes.
- Replace terminal `uncertain` results with the stronger outcome supported by
  deterministic evidence and successful publication.
- Persist canonical terminal state before completion callbacks and process
  termination, preserving publication references when later infrastructure
  reporting fails.
- Treat conflicting workflow failures as separate infrastructure anomalies
  instead of overwriting finalized worker-domain results.
- Keep noncritical post-publication failures from changing the mission outcome
  or producing a nonzero exit.

## Compatibility and backend enforcement

Legacy result, domain-finished, partial-result, and implementation-evaluated
payloads reference the same canonical terminal-result ID and outcome. Completion
callbacks now include the canonical payload, terminal revision, and authority so
the RustGrid control plane can enforce conditional updates and keep workflow
metadata separate from immutable domain-result fields.

The RustGrid control plane still owns database and workflow reconciliation.
Artifact publication does not update the production backend's agent download
URL and checksum automatically; deployment must pin the exact v1.4.34 Linux
archive and SHA-256 from the completed protected release workflow.

## Verification

Formatting, strict Clippy across all targets and features, dependency policy,
secret and generated-contract checks, packaged-source compilation, and the full
locked test suite pass. Regression coverage includes healthy non-complete exit
codes, deterministic outcome normalization, finality enforcement,
infrastructure anomalies and fallback, publication preservation, UI projection,
compatibility IDs, and degraded post-publication health.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.33. Do not replace
or mutate the v1.4.34 tag or release assets. Existing checkpoints and legacy
completion payload consumers remain backward readable.
