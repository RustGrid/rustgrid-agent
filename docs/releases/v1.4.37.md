# rustgrid-agent v1.4.37

This patch release makes hosted terminal acknowledgement durable and keeps the
worker's canonical domain result authoritative when callback delivery or later
workflow reconciliation is degraded.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Persist the canonical terminal result and the exact completion callback
  envelope before attempting network delivery.
- Use deterministic terminal-result and idempotency identities with bounded
  retry and durable restart replay.
- Track callback acknowledgement separately from mission outcome and process
  health, with stable telemetry for retry and recovery decisions.
- Resolve completion from typed graph, validation, remaining-work,
  publication, and external-review evidence instead of ticket-specific rules.

## Fixed

- Keep healthy complete, partial-reviewable, externally pending, blocked,
  cancelled, and failed outcomes stable when the final callback is delayed or
  missing.
- Prevent later workflow or runner observations from overwriting a finalized
  worker-domain result.
- Recover an unacknowledged persisted callback after restart without rerunning
  the mission or changing its terminal outcome.
- Reject callbacks whose result ID, revision, authority, compatibility status,
  execution identity, or process-exit evidence does not match the canonical
  result.

## Compatibility and deployment order

The completion request fields are additive, but the RustGrid backend validates
request bodies strictly. Deploy the backend migrations and contract from
`cf30e440c0ce8774430e23c4a3880b95443dc494` before pinning hosted workers to
v1.4.37. AgentOps commit `887b0a8725ec9e32f35de38d1e4ac80ec0ddc47e`
renders callback degradation as secondary infrastructure health without
changing the mission result.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. After the protected release completes,
pin the exact v1.4.37 Linux archive URL and SHA-256 published by the workflow.

Regression coverage includes deterministic callback identity, accepted-response

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL,
checksum, container deployment, and Homebrew installations to v1.4.36. Do not
replace or mutate the v1.4.37 tag or release assets. The backend additions are
forward-compatible and may remain deployed during an agent rollback.
