# rustgrid-agent v1.4.9

This release makes hosted AI request registration safely retryable before
provider dispatch while preserving one semantic model call across worker
sessions and transport attempts.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Separate the stable semantic identity of an AI call from each
  worker-session registration attempt.
- Retry proven pre-dispatch registration failures up to three times with
  bounded jitter without reinitializing the repository, notebook, or phase.

## Fixed

- Preserve the same execution attempt, call index, phase, and semantic call
  across automatic registration retries.
- Keep registration retries outside model-call and actual-cost accounting.
- Fail closed when a legacy or interrupted dispatch may already have contacted
  the provider.
- Emit precise registration attempt, gateway status, provider-contact, and
  reservation reconciliation telemetry without relying on ambiguous legacy
  provider status.

## Compatibility and deployment

Before pinning canonical hosted workflows to v1.4.9, deploy RustGrid backend
commit `371a030` and apply
`0071_execution_ai_semantic_calls.sql`. The migration introduces
execution-attempt-scoped semantic calls, transport registration attempts,
dispatch leases, and reservation reconciliation.

AgentOps commit `83ff6d7` displays registration retries, precise conflict
causes, and exhaustion messaging. The worker remains compatible with older
gateway responses, but it does not automatically retry an ambiguous legacy
failure because duplicate provider dispatch cannot be ruled out.

Artifact publication does not deploy the RustGrid backend, AgentOps, database
migration, or canonical workflow changes.

## Rollback

If rollback is required, stop new hosted dispatches and return canonical
workflows to `v1.4.8`. Do not replace or mutate existing tags or release
assets. Leave migration 0071 in place during an application rollback.
