# rustgrid-agent v1.4.13

This patch release makes hosted GitHub Actions completion reporting distinguish
finished implementation awaiting external review from work that still needs
source changes or automated verification.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Report mission outcome, implementation completeness, verification readiness,
  evaluator source, and worker process health as separate completion
  dimensions.
- Classify manual QA, accessibility, visual, product-approval, and deployment
  checks as pending external review with an explicit review checklist.
- Apply the project verification policy when deciding whether missing browser
  E2E coverage is mandatory for a theme change or remains external review.
- Reserve four diff-review calls and six completion-evaluation calls for a
  signed 60-call mission.
- Reallocate unused implementation capacity to diff review and completion
  evaluation, and retry malformed or rejected evaluator results while budget
  remains.
- Emit cache-observability telemetry for cache-eligible stable prefixes,
  provider cache reads, cold starts, tool-order changes, stable-prefix changes,
  and zero cache reads.

## Fixed

- Prevent a complete implementation that only awaits human review from being
  marked partial or resumable.
- Use `partial_result` only when implementation or automated verification
  remains; report finished work awaiting review as
  `awaiting_external_review`.
- Reconcile model evaluation with authoritative worker declarations,
  acceptance criteria, diff evidence, validation results, browser policy, and
  unrecovered tool failures before choosing a terminal outcome.
- Preserve structured completion evidence in both result events and the
  completion callback.

## Compatibility and deployment

RustGrid must accept the structured completion evaluation and the
`awaiting_external_review`, `partial_result`, and `blocked` completion states
before this worker version is pinned in the canonical GitHub Actions workflow.
AgentOps must render the independent implementation and verification
dimensions for operators to see the complete lifecycle.

Project metadata may provide `project_verification_policy` or the legacy
`browser_test_policy`. Without an explicit policy, manual browser verification
remains external review and browser E2E coverage is not made mandatory solely
by the worker.

Artifact publication updates the rustgrid-agent GitHub release, native
binaries, Homebrew formula, crate archive, SBOM, attestations, and container.
It does not deploy RustGrid or AgentOps and does not update the canonical
workflow pin.

## Verification

Regression coverage verifies deterministic external-review classification,
browser-policy enforcement, review-pending pull requests, evaluator
reconciliation, cache-observability diagnostics, finalization budget reserves,
and unused-capacity reallocation.

The complete Rust test suite, strict Clippy, npm quality gate, release build,
formatting, packaging, and diff checks must pass for this release candidate.

## Rollback

Stop new hosted dispatches before returning canonical workflows to v1.4.12.
Do not replace or mutate existing tags or release assets. Existing draft pull
requests and structured completion results remain available for inspection and
continuation according to their reported mission outcome.
