# rustgrid-agent v1.4.41

This patch release separates repository-operation verification from automated
validation and makes lifecycle invariants explicitly phase-scoped.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Represent repository-operation verification, implementation-barrier proof,
  validation-gate results, diff review, completion evaluation, and publication
  evidence as distinct typed proof classes.
- Register lifecycle invariants centrally with explicit scopes, required
  evidence, and producer-order validation at worker startup.
- Resolve implementation, barrier, validation, review, completion,
  publication, and terminal phases deterministically from the execution graph.
- Emit structured invariant checks, barrier state, future-evidence suppression,
  and next-node selection events with graph revision and repository identity.
- Resolve resumability once and preserve its reason, next unresolved node, and
  repository fingerprint in the canonical terminal result and callback.

## Fixed

- Do not require validation evidence merely because one implementation target
  became verified and completed.
- Continue directly through multiple source and test mutations, successful
  fallback repair, and already-applied operations until every required
  implementation node is satisfied.
- Admit validation only after the implementation barrier and require passed
  evidence bound to the full current repository fingerprint before validated
  review, completion, or normal publication.
- Mark validation evidence stale after a later repository mutation so repaired
  work reruns the relevant gate.
- Classify real lifecycle defects as resumable
  `OrchestrationStateInvariantFailure` values with specific invariant codes and
  the actual execution phase instead of initialization or generic failures.
- Preserve completed mutation evidence and resume from the next unresolved
  implementation node without rediscovery or remutation.

## Compatibility and deployment order

The CLI commands, signed manifest, hosted HTTP endpoints, reducer ordering,
repair-budget isolation, callback outbox, and terminal authority remain
unchanged. New evidence variants and resumability metadata are additive, while
legacy completed and already-applied checkpoints retain replay compatibility.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. After the protected release completes,
pin the exact v1.4.41 Linux archive URL and SHA-256 published by the workflow.

## Verification

The release candidate passes formatting, strict Clippy across all targets and
features, 600 library tests, 14 API contract tests, 10 CLI tests, 8 hosted
orchestrator replay tests, the repository build, and compilation from the
packaged 195-file source archive.

Regression coverage includes multi-target implementation sequencing,
repository-operation evidence, future-evidence rejection, implementation
barriers, fallback and already-applied continuation, fingerprint-bound and
stale validation, invariant taxonomy, canonical resumability, and resume from
the next unresolved node.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL,
checksum, container deployment, and Homebrew installations to v1.4.40. Do not
replace or mutate the v1.4.41 tag or release assets. Additive checkpoint,
evidence, telemetry, and terminal fields may remain stored during rollback.
