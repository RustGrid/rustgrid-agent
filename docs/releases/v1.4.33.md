# rustgrid-agent v1.4.33

This patch release makes hosted mutation targets operation-aware across existing
files, new files, deletions, renames, and moves. Missing paths are interpreted
from the accepted operation instead of being treated as universal repository
inspection failures.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Add typed `TargetOperation`, `TargetStateProbe`,
  `TargetInspectionOutcome`, `CreateTargetSpecification`, and
  `CreatedTargetEvidence` contracts to the execution graph.
- Require accepted implementation plans to state whether each target modifies,
  creates, deletes, renames, or moves a repository path.
- Build operation-specific target context: exact current evidence for existing
  files, source and destination constraints for relocations, and neighboring
  repository conventions and intent evidence for new files.
- Expose only mutation tools compatible with the accepted operation and reject
  provider tool mismatches before execution.
- Emit `worker.target_state_probed`,
  `worker.new_target_absence_confirmed`,
  `worker.target_operation_conflict`, `worker.create_target_started`,
  `worker.create_target_completed`, and
  `worker.target_operation_verified` with structured decision fields.

## Fixed

- Do not read an absent `CreateNew` target as though it were an existing file.
- Create repository-relative files atomically, validate parent-directory policy,
  reject traversal and protected metadata paths, verify exact content, and
  detect concurrent destination creation without overwriting it.
- Delete and relocate files through operation-specific tools with source hashes,
  destination constraints, and race-safe no-clobber behavior.
- Treat an absent deleted target or an evidence-matching created or relocated
  target as a successful `AlreadyApplied` state.
- Preserve earlier applied nodes, graph evidence, and the repository diff when
  a later target conflicts; reviewable partial work can continue through
  incomplete review and draft publication.
- Classify target-state conflicts and inspection failures with typed categories
  and stable codes instead of `orchestration_initialization_failed`.

## Generic operation contract

Operation selection and validation depend only on accepted plan metadata,
repository paths, persisted evidence, content hashes, and filesystem state.
Production logic contains no ticket names, ecosystem-specific filenames,
framework assumptions, UI roles, or scenario-specific values.

## Compatibility, security, and known limitations

Legacy `new_file` plan metadata remains readable and is normalized to
`CreateNew`; new provider plans must supply an unambiguous operation. Mutation
tools remain repository-scoped, reject traversal and protected metadata paths,
and never expose credentials or unrestricted filesystem access.

The RustGrid control plane still owns final workflow reconciliation. Artifact
publication does not update the production backend's agent download URL and
checksum automatically; deployment must pin the exact v1.4.33 Linux archive
and SHA-256 from the completed protected release workflow.

## Verification

Formatting, strict Clippy for all targets and features, dependency policy,
package verification, and the complete locked test suite pass. Coverage includes
all operation-state combinations, create safety, parent policy, no-clobber
relocation, evidence-backed `AlreadyApplied`, graph-progress preservation,
incomplete review, deterministic replay, and terminal-outcome preservation.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.32. Do not replace
or mutate the v1.4.33 tag or release assets. Existing checkpoints remain
backward readable.
