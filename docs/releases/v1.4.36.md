# rustgrid-agent v1.4.36

This patch release corrects validation-repair outcome semantics. Repair intent
is now independent from the original implementation intent, so an earlier
successful mutation cannot incorrectly prove that a later validation failure
has been repaired.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Model implementation and validation-repair intents separately and bind each
  repair attempt to structured assertion evidence.
- Persist typed repair attempts, target selection and progression, no-change
  results, independent target state, and terminal repair decisions.
- Expose repair lifecycle transitions through structured telemetry and include
  unresolved repair details in draft partial-result summaries.
- Restore hosted lifecycle decisions from durable typed repair evidence during
  replay and recovery.

## Fixed

- Keep a validation failure unresolved until the corresponding checks pass on
  the current repository state.
- Prevent `Applied` or `AlreadyApplied` implementation state from satisfying a
  distinct validation-repair intent.
- Treat identical repair output as a typed no-change result rather than a
  successful repository mutation, then continue across other eligible targets.
- Preserve useful reviewable changes as a healthy draft partial result when the
  repair budget or eligible targets are exhausted.
- Avoid collapsing unresolved validation repair into orchestration
  initialization failure when the typed lifecycle fallback is available.

## Compatibility and backend deployment

The repair evidence and lifecycle fields are additive and replay-safe. Existing
hosted mission, journal, telemetry, publication, and completion payload shapes
remain compatible.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. Deployment must pin the exact v1.4.36
Linux archive URL and SHA-256 from the completed protected release workflow.

## Verification

Formatting, strict Clippy across all targets and features, dependency policy,
secret and generated-contract checks, packaged-source compilation, JavaScript
quality gates, and the full locked test suite pass. The release container is
also smoke-tested and scanned for fixable high-severity vulnerabilities.

Regression coverage includes assertion-bound repair intent, no-change output,
multi-target progression, failed-validation authority, journal replay,
structured telemetry, repair exhaustion, incomplete review, and healthy draft
partial publication.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, container deployment, and Homebrew installations to v1.4.35. Do not
replace or mutate the v1.4.36 tag or release assets. Existing journals remain
readable, but incomplete repair work should resume on v1.4.36.
