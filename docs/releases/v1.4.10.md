# rustgrid-agent v1.4.10

This patch release fixes hosted OpenAI Responses requests that reached the
provider with invalid metadata, preserves the provider's safe validation
diagnostic end to end, and prevents definite provider HTTP 400 responses from
being reported as stale request-registration conflicts.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Validate the startup provider envelope, metadata value types, function-tool
  definitions, strict tool schemas, duplicate tool names, schema depth, and
  model-facing options before repository work.
- Revalidate every exact agent and completion-evaluator request immediately
  before dispatch, including supported request fields, and validate strict
  structured-output schemas whenever `text.format` is present.
- Preserve typed provider-validation, authentication, rate-limit, timeout,
  server, gateway, registration, and dispatch-uncertain failure policies.
- Carry bounded safe provider error fields, request identifiers, explicit
  gateway status, model and adapter identity, provider-attempt counts, and
  reservation accounting through telemetry and terminal results.

## Fixed

- Send `metadata.model_call_budget` as the string required by the Responses API
  instead of an integer that the provider rejects with HTTP 400
  `invalid_type`.
- Treat a definite upstream HTTP 400 as
  `ai_provider_invalid_request` at `provider_dispatch`, with
  `provider_contacted: true` and a distinct nullable RustGrid gateway status.
- Never replace an authoritative provider rejection with the stale
  “AI request registration conflicted before provider dispatch” template.
- Restore phase capacity only when RustGrid explicitly reports
  `call_budget_consumed: false` and zero actual cost.
- Preserve the exact safe tool or schema path when startup validation fails,
  and retain bounded provider diagnostics large enough for the backend error
  contract.

## Compatibility and deployment

Before pinning canonical hosted workflows to v1.4.10:

1. Deploy RustGrid backend commit `7f71648` and apply
   `0072_execution_ai_provider_failures.sql`.
2. Deploy AgentOps commit `ec1e167` so nonterminal corrected-retry events cannot
   override later terminal failures and raw provider response bodies remain
   redacted.
3. Confirm the backend and AgentOps deployments are healthy before updating
   the workflow's agent version.

The backend performs at most one deterministic corrected retry after a provider
HTTP 400, and only when the corrected, locally valid payload differs. Provider
transport attempts remain separate from semantic model-call and actual-cost
accounting.

Artifact publication does not deploy the RustGrid backend, AgentOps, database
migration, or canonical workflow changes.

## Known limitations

- The worker restores phase capacity only when RustGrid provides explicit
  zero-call and zero-cost accounting; missing accounting remains fail-closed.
- This release cannot make older backend or AgentOps deployments understand
  the new provider evidence without the prerequisite deployments above.

## Verification

Local worker tests cover string-typed request metadata and the original invalid
integer shape, provider-failure precedence through a mock gateway, safe
diagnostic bounds, startup tool-schema paths, runtime request validation, and
non-billable phase-budget restoration.

## Rollback

If rollback is required, stop new hosted dispatches before returning canonical
workflows to `v1.4.9`. That version retains the malformed integer metadata, so
keep hosted execution stopped until a corrected worker is deployed. Do not
replace or mutate existing tags or release assets. Leave migration 0072 in
place during an application rollback.
