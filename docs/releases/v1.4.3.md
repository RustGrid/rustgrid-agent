# rustgrid-agent v1.4.3

This release makes hosted execution completion-aware so passing regression
gates cannot disguise a partial implementation as successful.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Added

- Hosted executions now create an implementation impact map before editing,
  review the final status and complete diff, and issue a structured
  implementation declaration.
- A fresh model context independently evaluates ticket requirements,
  acceptance criteria, changed paths, validation evidence, model-budget
  exhaustion, and unrecovered tool failures.
- Telemetry reports model-call allocation and consumption by phase, repository
  tool usage, changed-path count, evaluator status and confidence, and whether
  the branch is resumable.

## Changed

- Implementation completeness and technical validation are independent.
  Successful execution requires completeness `complete` and passing required
  technical gates.
- Discovery is bounded and batched, while completion review receives reserved
  model-call capacity.
- Partial, incomplete, or uncertain work is preserved on the deterministic
  branch in a prominently marked draft pull request. A later execution attempt
  continues from that branch and reconciles the pull-request title, body, and
  draft state.

## Fixed

- A model-call or cost-budget handoff with a valid partial diff can no longer
  become successful merely because tests and the production build pass.
- Unrecovered source-changing tool failures block automatic success.
- Final implementation declarations are invalidated by later edits and cannot
  be recorded until the model inspects the current changed paths and complete
  diff.
- Every acceptance criterion in the impact map must appear in the independent
  evaluation, and satisfied criteria must cite concrete changed-path evidence.

## Compatibility and deployment

The RustGrid control plane must accept `partial_result` as a distinct resumable
terminal execution result before this worker version is deployed. It must
retain the branch, commit, and draft-pull-request metadata, keep the ticket out
of review-ready state, and expose continuation on a later execution attempt.
Older control-plane versions accept only `completed`, `failed`, and
`cancelled`; they will reject a partial completion callback.

Artifact publication does not update canonical GitHub Actions workflow
references or deploy workers. Update the control-plane contract first, then
update workflow references to `v1.4.3`, regenerate affected workflows, and
complete staging certification against the exact published image digest before
production promotion.

## Rollback

If rollback is required, stop hosted dispatches and return canonical workflows
to `v1.4.2`. Version 1.4.2 preserves a budget-exhausted diff but can still infer
successful implementation from passing technical gates, so do not use it for
cross-cutting work where partial completion is unsafe. Do not replace or mutate
existing tags or release assets.
