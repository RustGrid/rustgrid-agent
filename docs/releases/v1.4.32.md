# rustgrid-agent v1.4.32

This patch release makes hosted validation repair evidence-driven and generic
across tickets, repositories, source layouts, assertion values, and component
roles. It also makes unresolved validation repair a legal, recoverable route to
an explicitly incomplete draft review.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Parse ANSI-decorated validation output into typed assertion failures with the
  test file, suite path, test name, source line and column, assertion kind,
  expected and received values, implicated paths, and bounded context.
- Refresh bounded current-fingerprint evidence for planned mutation targets and
  failing test paths before constructing repair evidence.
- Rank repair targets deterministically from assertion specificity, direct test
  imports, source-versus-test role, expected and received value evidence, and
  normalized semantic overlap.
- Add typed validation-repair actions for evidence construction, diagnosis,
  target selection, mutation, verification, and failed-gate reruns.
- Emit structured validation parsing, fallback, repair evidence, target
  ranking, context validation, transition comparison, and incomplete-review
  events.

## Fixed

- Do not invoke validation repair with null current content or a null target
  content hash when the selected target exists. Missing required evidence now
  fails closed as `repair_context_incomplete`.
- Do not silently treat recognized but partially parsed validation output as an
  empty set of failures. Emit a bounded parse-incomplete event and retain a
  conservative structured fallback record.
- Preserve already-applied source and test mutation nodes after focused
  validation failure.
- Permit the graph-selected repair-to-incomplete-diff-review transition when a
  safe diff exists but no valid repair was produced or repair budget is
  exhausted.
- Keep incomplete review distinct from completed review, draft-only, and
  eligible only for the `partial_reviewable` outcome.

## Generic repair-selection contract

Production ranking contains no ticket-specific component names, UI roles,
state labels, expected values, or scenario words. Ticket-specific examples are
test fixtures only. An unrelated state-machine fixture verifies that the same
evidence rules select a source repair target with arbitrary filenames and
values.

## Compatibility, security, and known limitations

The assertion fields and repair telemetry are additive and use serde defaults,
so existing persisted execution records remain readable. Raw validation output
is bounded before telemetry emission. Repair requests remain target-scoped and
do not include provider credentials, environment secrets, or unrestricted
repository content.

The RustGrid control plane still owns final workflow reconciliation. Artifact
publication does not update the production backend's agent download URL and
checksum automatically; deployment must pin the exact v1.4.32 Linux archive
and SHA-256 from the completed protected release workflow.

## Verification

Formatting, strict Clippy for all targets and features, and the complete locked
test suite pass. Coverage includes ANSI parsing, conservative parsing fallback,
generic evidence-based target selection, exact repair-context preparation,
repair checkpoint replay, applied-status preservation, incomplete review,
draft-only dependency overrides, and deterministic multi-mission replay.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.31. Do not replace
or mutate the v1.4.32 tag or release assets. Existing checkpoints remain
backward readable.
