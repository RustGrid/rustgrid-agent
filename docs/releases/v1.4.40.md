# rustgrid-agent v1.4.40

This patch release makes verified repository writes, graph completion,
validation admission, repair accounting, and cycle recovery converge through
one generic orchestration contract.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Route applied and already-applied repository results through one atomic
  reducer that finalizes the active attempt, completes the node, records
  evidence, clears active ownership, and recomputes dependencies.
- Persist the mutation lifecycle as proposed, validated, applied-unverified,
  verified, rejected, or conflicted state reconstructed from domain events.
- Derive validation readiness from a structured implementation proof containing
  required and completed counts, unresolved node IDs, graph revision, and the
  current repository fingerprint.
- Resolve mutation fallback and validation repair from independent persisted
  counters and explicit budget owners, without sharing an ambiguous repair
  allowance.
- Classify deterministic cycles by cause and reconcile successful repository
  evidence locally before invoking a terminal guardrail.
- Validate critical worker telemetry fields before emission, including node,
  operation, attempt, repair intent, budget owner, fingerprints, evidence, and
  before/after status.

## Fixed

- Prevent a successfully verified modification, creation, deletion, move,
  rename, or already-applied operation from remaining Ready, Running, active,
  or incorrectly Superseded.
- Finalize successful attempts with completion time, outcome, and resulting
  repository fingerprint in the same graph transaction as node completion.
- Keep recovered or superseded failure records independent from execution-node
  status and preserve original implementation completion during validation
  repair.
- Block validation while any required source or test-mutation node remains
  incomplete, including when partial-review dependency overrides exist.
- Fail closed with typed, resumable orchestration-state or repair-accounting
  failures when successful mutation evidence cannot converge or a repair tries
  to use an incompatible budget scope.
- Preserve semantic-decision deduplication, no-op graph revisions, bounded cycle
  detection, graph-derived progress projections, and canonical terminal-result
  authority.

## Compatibility and deployment order

The signed manifest, hosted HTTP endpoints, terminal callback, and CLI command
contracts are unchanged. The mutation lifecycle and validation-readiness fields
are additive; older checkpoints omit them and reconstruct lifecycle state from
their event journals during replay. Legacy repair field names remain accepted
on deserialization.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. After the protected release completes,
pin the exact v1.4.40 Linux archive URL and SHA-256 published by the workflow.

## Verification

The release candidate passes formatting, strict Clippy across all targets and
features, 593 library tests, 14 API contract tests, 10 CLI tests, 8 hosted
orchestrator replay tests, secret scanning, and compilation from the packaged
193-file source archive.

Regression coverage includes authoritative applied and already-applied
reduction, lifecycle replay, attempt finalization, failure/node separation,
implementation barriers, independent repair ownership, typed failure mapping,
cycle-cause reconciliation, structured telemetry contracts, semantic progress,
graph-derived projections, and canonical terminal precedence.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL,
checksum, container deployment, and Homebrew installations to v1.4.39. Do not
replace or mutate the v1.4.40 tag or release assets. Additive checkpoint and
telemetry fields may remain stored during an agent rollback.
