# rustgrid-agent v1.4.12

This patch release makes hosted GitHub Actions execution completion-first when
RustGrid authorizes a larger model-call budget.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Allocate a signed 60-call mission as 8 discovery calls, 4 planning calls, 45
  implementation and repair calls, 2 diff-review calls, and 1 completion
  evaluation call.
- Keep discovery and planning bounded as total capacity grows. The additional
  calls flow into implementation and repair rather than repeated exploration.
- Preserve early implementation pressure: the worker expects a first write
  attempt by call 17 and a successful write by call 22 even for a 60-call
  mission.
- Retain the latest three raw turn windows after checkpointing. The durable
  notebook, acceptance criteria, existing diff, validation evidence, and
  remaining work remain the authoritative continuation state.
- Accept consistent backend-signed budgets up to 100 calls without creating a
  worker-side product cap below RustGrid's signed policy.

## Fixed

- Prevent phase scaling from spending the larger budget on discovery, planning,
  and repeated finalization instead of completing the implementation.
- At 70% consumption, direct the worker to continue from its notebook and
  prioritize unmet acceptance criteria. At 90%, direct it to produce the
  smallest complete validated result.

## Compatibility and known limitations

RustGrid remains authoritative for cost control. The worker uses exactly the
budget carried consistently by the signed manifest and AI gateway policy; this
release does not let a run exceed that signed limit.

For the intended 60-call behavior, RustGrid must sign and deliver 60 through
every canonical budget field. Older manifests and smaller explicit budgets
remain supported.

Conversation compaction can require the model to reread a source file whose raw
tool output aged out of the three-window context. The durable notebook and
preserved repository diff prevent that reread from restarting the mission.

Artifact publication does not update the canonical GitHub Actions workflow pin
or deploy the RustGrid backend.

## Verification

Regression coverage verifies the exact 8/4/45/2/1 allocation, early-write
deadlines, 70% and 90% completion guidance, three-window context compaction,
legacy 20- and 40-call budgets, and consistent signed budgets through 100 calls.

The complete Rust test suite, strict Clippy, npm quality gate, release build,
formatting, and diff checks pass for this release candidate.

## Rollback

Stop new hosted dispatches before returning canonical workflows to v1.4.11 and
restoring RustGrid's prior signed budget. Do not replace or mutate existing
tags or release assets. Existing draft pull requests, worker notebooks, and
deterministic branches remain available for later continuation.
