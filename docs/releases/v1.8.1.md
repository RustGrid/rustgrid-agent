# rustgrid-agent v1.8.1

This patch release gets traced IDE sessions uploading again when RustGrid
reports that a telemetry batch was already recorded.

## Install or upgrade

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

Restart Claude Code after upgrading.

## Fixed

- **A replayed telemetry batch no longer stalls a session.** A session's
  first upload marks its run as started. Retries of that upload carried a new
  timestamp under the same idempotency key, so once RustGrid had stored one
  attempt it answered every retry with `409 telemetry idempotency key was
  reused with different data`. The worker kept retrying, and the session's
  prompts, replies and summary never uploaded. That answer now counts as
  recorded, because every event has a stable id that RustGrid already holds,
  and the session's other uploads go through. An open session that was stuck
  this way catches up on its next hook after the upgrade; an ended one catches
  up with `rustgrid-agent trace flush --session <session-id>`.

## Compatibility

- Works with the same RustGrid as v1.8.0. Session state written by v1.8.0 or
  v1.7.0 is read as is.
