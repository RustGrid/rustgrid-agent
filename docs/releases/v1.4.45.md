# rustgrid-agent v1.4.45

This patch release fixes the validation handoff after a successful repository
repair so the scheduled originating validation command actually starts.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Fixed

- Consume an already-scheduled `RunValidation` decision for a validation-repair
  session exactly once when the worker enters the existing validation runner.
- Start the normal validation process after repair and retain the existing
  process-start, process-completion, pass, failure, and next-gate lifecycle.
- Avoid repeatedly selecting the same validation decision until the semantic
  cycle guardrail terminates an otherwise successful repair mission.

## Compatibility and deployment order

Discovery, planning, repository mutation, validation-repair nodes, publication,
terminal handling, budgets, and cycle detection are unchanged. Initial
validation and unrelated execution decisions retain their existing behavior.

Artifact publication does not update the production RustGrid backend's agent
download URL and checksum automatically. After the protected release completes,
pin the exact v1.4.45 Linux archive URL and SHA-256 published by the workflow.

## Verification

The release candidate passes formatting, strict Clippy, 611 library tests, 14
API contract tests, 10 CLI tests, 8 hosted-orchestrator replay tests, and
packaged-source compilation using the pinned Rust 1.94 toolchain. The focused
regression proves that a scheduled post-repair validation runs exactly once,
emits normal process-start and process-completion events, and does not trigger
the orchestration cycle guardrail.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL,
checksum, container deployment, and Homebrew installations to v1.4.44. Do not
replace or mutate the v1.4.45 tag or release assets.
