# rustgrid-agent v1.4.18

This patch release fixes hosted preparation, mutation, reconciliation,
validation, and publication so a healthy five-target implementation can finish
without validating an unchanged tree or exhausting its model budget.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Persist implementation substates for preparation, mutation, repair, and
  validation readiness, together with typed tool-progress outcomes.
- Present one planned target at a time with compact authoritative context and
  one guided recovery turn when the first write is delayed.
- Reserve a shared implementation-and-repair pool while retaining capacity for
  deterministic diff review and completion evaluation.
- Apply five-target performance limits of 20 total model calls, 10
  implementation and repair calls, ten minutes, and an estimated EUR 2.

## Fixed

- Prevalidate batch reads, preserve partial successes, retry valid failed paths
  individually, and distinguish productive reads from recoverable failures.
- Prevent zero-diff validation when required targets remain planned, and report
  the condition as a structured healthy, resumable domain outcome.
- Include repository identity, HEAD, tracked edits, untracked file contents,
  and dependency locks in source-tree fingerprints and validation evidence.
- Run the focused gate first, stop broad gates after a focused failure, reuse
  exact-tree evidence, and rerun invalidated required gates once after repair.
- Normalize impact-map path references, retain valid planning fragments during
  repair, and keep informational write-progress reports from claiming mutation.
- Reconcile committed and dirty paths as one resumed implementation, retain
  previously applied targets, and publish useful partial or review-pending work
  without converting healthy outcomes into generic failures.
- Bound AI requests and retries by the execution deadline and conservatively
  account provider calls that omit usage details.

## Compatibility, security, and known limitations

Existing notebook records remain readable because the new substate, read-range,
discovery, and tool-progress fields are defaulted. Existing pull requests and
committed hosted branches are reconciled with new dirty work before validation.
No new repository or GitHub credential scope is introduced; repository reads
remain path-prevalidated and writes remain constrained to authorized planned
targets.

Artifact publication updates the GitHub release, native binaries, Homebrew
formula, SBOM, attestations, and container. It does not deploy a production
worker. Production must be updated separately to the exact v1.4.18 Linux
archive URL and SHA-256 after the protected release workflow completes.

## Verification

The complete locked worker suite passes 313 unit tests, 14 API-contract tests,
and 10 CLI tests. Formatting and strict Clippy pass with warnings denied.
Focused coverage proves recoverable reads, guided first-write recovery,
five-target mutation, zero-diff blocking, repository fingerprints,
tree-bound validation, resumed committed-plus-dirty reconciliation, hard time
and cost limits, commit and push, mocked pull-request publication, terminal
reporting, and a successful workflow exit.

## Rollback

Stop new hosted dispatches before restoring the RustGrid worker download URL
and SHA, canonical workflows, and Homebrew installations to v1.4.17. Do not
replace or mutate the v1.4.18 tag or release assets. The added notebook and
telemetry fields are backward-compatible and remain available for audit and a
later resume.
