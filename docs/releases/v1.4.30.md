# rustgrid-agent v1.4.30

This patch release fixes hosted validation-repair reconciliation so useful,
already-applied repository changes survive a failed focused test and can be
published safely as an explicitly incomplete draft pull request.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Introduce a typed `ReviewIncompleteDiff` decision and draft-only dependency
  overrides for failed or pending validation gates.
- Record mutation completion separately from validation correctness so applied
  source and test changes remain authoritative after a code-validation failure.
- Parse focused-test assertions into structured names, locations, expected and
  received values, implicated paths, diagnosis evidence, and repair intent.
- Restrict validation repair to one selected target from a bounded implicated
  set, with a mutation or typed `NoValidRepair` as the required result.
- Account for validation diagnosis and validation-repair mutation calls
  independently from initial and repaired target mutations.

## Fixed

- Convert a no-mutation validation repair with a non-empty safe diff into
  deterministic incomplete review, partial evaluation, and draft publication
  instead of `orchestration_initialization_failed`.
- Preserve failed focused validation and pending suite/build gates in recovery
  state and draft pull-request documentation without claiming completion.
- Keep worker process health healthy when authentication, checkout, provider
  contact, mutation, validation execution, and graph persistence succeeded but
  the mission remains validation-incomplete.
- Enforce a selected `replace_file` fallback by exposing and accepting only the
  replacement tool.
- Resume partial-reviewable work at validation repair without repeating
  discovery, planning, or applied mutations.

## Compatibility, security, and known limitations

This release makes additive execution-graph and recovery-state changes. Older
persisted records remain readable through defaulted serialized fields. Draft
dependency overrides cannot authorize a complete outcome and do not erase or
convert failed validation evidence.

Hosted execution still requires the canonical GitHub Actions OIDC and Linux
cgroup-v2 containment boundary. Artifact publication does not update the
production backend's agent download URL and checksum automatically; deployment
must pin the exact v1.4.30 Linux archive and SHA-256 from the completed protected
release workflow.

## Verification

The complete locked suite passes 504 unit tests, 14 API-contract tests, 10 CLI
tests, and 8 hosted-orchestrator replay tests. Formatting and strict Clippy pass
for all targets and features. Regression coverage includes applied-node status
preservation, structured Vitest parsing, bounded repair tools, typed no-mutation
reconciliation, draft-only dependency overrides, failed and pending gate
reporting, validation-specific budget accounting, and partial-run resumption.

## Rollback

Stop new hosted dispatches before restoring the backend worker download URL and
SHA, canonical workflows, and Homebrew installations to v1.4.29. Do not replace
or mutate the v1.4.30 tag or release assets. Existing checkpoints remain
backward readable.
