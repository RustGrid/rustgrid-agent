# rustgrid-agent v1.4.7

This release hardens the hosted discovery-to-planning boundary so a valid
implementation impact map survives recoverable persistence failures and a
single tightly scoped supplemental call can repair only the missing artifact.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- Accept the canonical manifest-v4 `model_call_budget` contract together with
  requested, resolved, received, source, and clamp audit fields.
- Require the signed manifest budget to match the execution and AI-gateway
  budget fields exactly. Any mismatch fails before the first model request
  with `execution_budget_mismatch`.
- Continue accepting explicit legacy manifest-v3 custom budgets without
  applying a worker-side default.
- Add an `artifact_repair` phase that permits one supplemental model call and
  exposes only `record_impact_map`. The repair call reuses the existing
  discovery notebook and cannot read, search, or mutate the repository.
- Report budget policy, semantic artifact status, persistence status, and
  separate budgeted and worker model-call totals in notebook, request, and
  telemetry metadata.

## Fixed

- Recover a strict impact map from stored tool arguments, assistant JSON, or
  preserved notebook discovery progress when the primary tool invocation does
  not produce a usable tool result.
- Merge fallback evidence only from repository files and searches already
  recorded by the worker, and reject unknown impact-map fields.
- Keep a semantically valid impact map available when durable event persistence
  fails, retry the checkpoint idempotently, and continue into planning.
- Preserve exact artifact, transition, notebook, tool-event, gateway, and safe
  failure diagnostics instead of collapsing them into a generic hosted-agent
  failure.
- Resume directly in planning when a valid impact map was checkpointed, or in
  `artifact_repair` when discovery finished without one.

## Compatibility and deployment

Before pinning canonical workflows to v1.4.7, deploy the matching RustGrid
backend changes:

- default hosted `model_call_budget` of 40;
- canonical manifest-v4 requested, resolved, source, clamp, execution, and
  gateway budget fields with exact worker-visible agreement;
- AI-gateway accounting that identifies the one supplemental
  `artifact_repair` call separately from the signed mission budget;
- idempotent impact-map checkpoint persistence and resume state;
- additive artifact semantic, persistence, failure, and model-call telemetry.

Regenerate and deploy AgentOps from the updated OpenAPI contract so launch and
retry forms send the canonical budget and the execution UI displays resolved
budget, clamp state, artifact status, and recoverable repair progress.

The canonical workflow must continue accepting only `execution_id` and
`dispatch_nonce`. The selected budget remains authenticated manifest policy,
not an unsigned workflow input.

Artifact publication does not deploy those backend, AgentOps, or canonical
workflow changes.

## Rollback

If rollback is required, stop new hosted dispatches and return canonical
workflows to `v1.4.6`. Version 1.4.6 does not require the manifest-v4 budget
agreement or supplemental artifact-repair contract. Do not replace or mutate
existing tags or release assets.
