# rustgrid-agent v1.4.6

This release gives broad hosted coding missions a hard phase-aware execution
budget so additional model calls produce implementation progress instead of
unbounded repository exploration.

## Install or upgrade

On macOS with Homebrew:

```sh
brew update
brew upgrade RustGrid/tap/rustgrid-agent
```

For a new installation:

```sh
brew install RustGrid/tap/rustgrid-agent
```

## Changed

- A signed 40-call hosted mission is divided into hard allocations:
  - discovery: 8 calls;
  - planning: 4 calls;
  - implementation and repair: at least 20 calls;
  - diff review: 4 calls;
  - completion evaluation: 4 calls.
- Discovery and planning cannot borrow reserved implementation capacity. Calls
  saved by finishing either phase early roll forward only into implementation
  and repair.
- Custom budgets use deterministic `20/10/50/10/10` proportional allocation
  and keep at least half of the total for implementation and repair. Hosted
  coding budgets below 10 calls are rejected as non-viable.
- Discovery must produce a structured implementation impact map and planning
  must produce a machine-readable implementation plan before source mutation.
- The default 40-call progress thresholds require the impact map by call 8,
  plan by call 12, first write attempt by call 16, successful write by call 20,
  and diff review beginning at call 33.
- Repository search output is grouped and deduplicated. Duplicate searches and
  a fourth consecutive search are rejected, and post-discovery searches must
  target a mapped path or concrete failure.
- The worker maintains a compact versioned notebook across model calls and
  emits it in durable execution events for control-plane checkpointing and
  continuation.
- Diff review is paged and bound to an immutable SHA-256 so the implementation
  declaration cannot be accepted until the complete diff was inspected.

## Fixed

- Final model messages can no longer bypass a missing impact map, plan, diff
  review, or implementation declaration.
- Unrecovered write failures remain completion blockers; a later write is
  considered recovery only when it retries the same intended operation.
- Validation repair now replaces the earlier implementation declaration before
  independent completion evaluation.
- Failure events preserve the active phase, exact safe failure code, call
  limits and consumption, tool-operation counts, last successful action,
  recoverability, recommended action, and request correlation when available.
- Passing technical gates still cannot turn incomplete functional work into a
  successful mission.

## Compatibility and deployment

The worker accepts a signed 40-call manifest unchanged and continues to support
lower custom budgets from 10 calls upward. It does not itself change the
RustGrid control-plane default from 20 to 40.

Before pinning canonical workflows to v1.4.6, deploy the matching RustGrid
backend changes:

- default hosted `maximum_model_calls` of 40 and minimum of 10;
- a signed phase-allocation policy in the execution manifest;
- AI-gateway validation, enforcement, persistence, and billing attribution for
  the active phase;
- worker-notebook checkpoint storage and continuation inheritance;
- resumable `partial_result` completion with draft pull-request verification;
- additive structured failure and completion-evaluation fields.

Regenerate and deploy AgentOps from the updated OpenAPI contract so launch and
retry forms preserve 40 calls, phase usage and guardrails are visible, and
partial work exposes “Continue implementation.”

The canonical workflow must continue accepting only `execution_id` and
`dispatch_nonce`. The selected budget remains authenticated manifest policy,
not an unsigned workflow input.

Artifact publication does not deploy those backend, AgentOps, or canonical
workflow changes.

## Rollback

If rollback is required, stop new hosted dispatches and return canonical
workflows to `v1.4.5`. Version 1.4.5 restores the advisory discovery target and
does not understand the v1.4.6 phase/notebook contract. Do not replace or mutate
existing tags or release assets.
